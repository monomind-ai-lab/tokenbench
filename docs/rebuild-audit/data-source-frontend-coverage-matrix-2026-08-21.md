# TokenBench data-source → frontend coverage matrix

**Audit date:** 2026-08-21

**Code reviewed:** `codex/frontend-rebuild` at `c4241b7`

**Scope:** planning and evidence audit only. No deployment, endpoint activation, data refresh, migration, or UI-design change was performed.

## Executive finding

The repository has a sound immutable-evidence design, substantial source adapters, strict v1 schemas, and Next server projectors that preserve unavailable values. It is not yet one coherent launch-ready producer path:

1. The canonical origin currently serves a fresh legacy catalog but stale legacy benchmark data.
2. The canonical strict-v1 lifecycle, rankings, and subscription paths are not publicly routed: at audit time they resolved to the site HTML fallback rather than contract JSON.
3. The Next app bridges that gap with legacy-response compatibility projectors and, for LiveBench, a server-side direct upstream loader. That is useful for a local review, but it bypasses the intended immutable-R2 → staged-D1 → published-API boundary.
4. Exact cross-source maps are deliberately empty. This correctly prevents display-name joins, but leaves capability, provider-route pricing, human preference, and subscription-plan facts only partially composable.

The result is not a generic “blank UI” problem. Each surface has a different failure mode: stale producer data, missing public contract route, intentionally missing source fact, strict join failure, or a projection that can only render the source it actually received.

### Status terms used below

- **populated** — source facts have an active published path for the stated field; freshness may still be `stale`.
- **wired-but-unpopulated** — schema/adapter/UI location exists, but no active source record/fact fills it.
- **partial** — only a declared subset of a row’s required fields or routes is available.
- **missing join** — source facts exist but lack an approved exact identity/route/taxonomy binding.
- **not ingested** — source may be known or reviewed in docs, but it is not part of an active publication path.
- **source-does-not-publish** — the required measurement is not published by any approved current source; it must remain unavailable.

`null` is never interpreted as `0`, free, disabled, or perpetual availability.

## Immutable publication and identity boundary

```text
approved upstream artifact / official provider page
  → bounded retrieval + source-specific projection
  → immutable R2 bytes, hashes, source manifest
  → attempt-owned, revisioned D1 staging
  → validation and exact identity/route checks
  → atomic publication pointer + materialized API response
  → Pages API v1 envelope
  → Next server loader/projector
  → explicit available / partial / unavailable UI state
```

The intended boundary is implemented across the catalog and benchmark workers, migrations, and [`contracts/ui-data-contract/v1`](../../contracts/ui-data-contract/v1). The current Next compatibility layer is explicitly transitional: [`published-compatibility.server.ts`](../../apps/web/src/lib/published-compatibility.server.ts) reads legacy catalog/directory/profile JSON and projects it to v1-shaped views; [`livebench-upstream.server.ts`](../../apps/web/src/lib/livebench-upstream.server.ts) fetches a commit-pinned LiveBench release at Next request time. Neither should be the final production data authority.

**Allowed join keys only:** `modelKey`, `sourceId`, `sourceModelId`, `canonicalSlug`, `routeId`, `providerId`, `catalogRevision`, `benchmarkRevision`/release ID, and reviewed plan ID. The exact source-alias map and subscription model map are presently empty ([`model-aliases.ts`](../../src/benchmarks/model-aliases.ts), [`subscription-model-map.ts`](../../src/benchmarks/subscription-model-map.ts)); display names are never a fallback key.

## Prioritized implementation sequence — do not start without approval

1. **Establish the launch contract boundary (P0).** Make the v1 Pages handlers publicly routable after authorized migration/deployment work; prove every advertised method returns v1 JSON rather than the HTML fallback. Do not change the Next design in this step.
2. **Publish one coherent real evidence set (P0).** Apply only approved additive migrations, execute the catalog and LiveBench/benchmark cycles through the existing checkpointed process, and verify immutable R2 evidence, D1 counts, active pointers, and response cache before exposing it.
3. **Make identity/taxonomy review a producer input (P0).** Add a revisioned, reviewer-evidenced registry for source model IDs, canonical slugs, route IDs, subscription plan bindings, and category-slot mappings. Begin with a small known set; retain rejected/unknown records.
4. **Replace transitional Next loading (P0).** Remove server-side LiveBench upstream retrieval and legacy-shaped compatibility as the production path. Next should consume only the active v1 producer; existing presentation projectors remain, but they receive explicit availability/provenance envelopes.
5. **Close subscription scope deliberately (P0).** Decide whether Perplexity and Microsoft are launch requirements. Publish reviewed first-party records and bindings, or retain seven slots with unavailable reasons. Promote no dynamic/stale entitlement to a capacity recommendation.
6. **Add source-level freshness and field receipts (P1).** Expose source observed/effective/review status in v1 for catalog plans/routes, so a fresh catalog pointer cannot conceal a stale provider value.
7. **Add runtime only as a separate source program (P1/P0 if SLA is promised).** Define a source, methodology, keys, retention, cadence, and user-facing uncertainty before enabling runtime filters/charts.
8. **Optional enrichment only after rights review (P2).** Consider AI Pricing Guru as a separately attributed price-history corroborator only if permission and product owner approval are written down; do not use it for subscription truth.

## Test and freshness gates

1. **Source retrieval gates:** URL allowlists, robots policy, response-size bounds, conditional requests, source schema, SHA/hash/blob verification, prohibited Artificial Analysis scan, license/attribution checks.
2. **Publication gates:** R2 manifest before D1 staging; bounded attempt-owned staging; source row/count reconciliation; active-pointer transaction; stale publication epoch rejection; response-cache revision must match published evidence revision.
3. **Freshness gates:** catalog source/revision ≤36h for a fresh badge; benchmark-derived evidence ≤8d for a fresh badge. Failure after a valid prior publication must serve labelled last-good; only a cold system is unavailable.
4. **Identity gates:** all joins must assert source ID/model key/source model ID/canonical slug/route ID/revision equality. Test a display-name collision, source-key collision, ambiguous LMArena row, unreviewed LiveBench configuration, and rejected alias.
5. **Contract transport gates:** every v1 URL must return v1 JSON, not document HTML; exact request echo; media-type/ETag/304; query/cursor isolation; `null` plus reason/provenance; 404 cold-source and 503 projection failure semantics.
6. **Frontend projector gates:** one fixture each for populated, stale, partial, missing join, and unavailable. Assert reader text `-`/reason, disabled runtime or positive-cache controls, no fallback fixture, preserved ordered comparison URL, and visible source/freshness.
7. **Cross-page acceptance gates:** real active response review of Home, Models, profile, lifecycle, Compare, Popular Models, every leaderboard child, Subscribe vs API, Make It Yours, price-performance, Data Sources, and articles at narrow/wide widths. Capture source/revision/freshness for each reviewed page.
8. **Content gates:** article inventory remains 6 guides / 2 prototype insights / 0 news unless a separately approved editorial source changes it; prototype labels and source links must survive SSR and client navigation.
